## Section 2 · THE FIVE-TIER HIERARCHY

**Eyebrow:**
`THE ORGANIZATIONAL BLUEPRINT`

**Section Headline:**
One hierarchy. Five tiers. From atomic tool calls to a self-running company.

**Section Subheadline:**
The hierarchy prevents monolithic prompt sprawl. Strategy stays at the top. Tool execution stays at the bottom. Each layer does exactly what it was built for — and the composition rule is simple: build up.

**Composition Rule (displayed prominently):**
> An **Action** wraps a Tool. Actions combine into a **Skill**. Skills compose into an **Agent**. Agents orchestrate into a **Process**. Processes sustain a **Loop**. → That's your company.

### Tier 1 — Loop (The Standing Function)

**Role Analogy:** The Whole Department — or the Whole Company

**Description:**
The largest unit of work in the platform. A Loop is a continuously-running business function that never terminates — it owns goals, KPIs, schedules, and a portfolio of Processes that fire on triggers, timers, and events. Where a Process completes and ends, a Loop persists.

Your entire company runs as one Loop: **Sheel**.

**Example:** The Growth & Customer Acquisition Loop owns lead generation, qualification, nurture, and conversion Processes. It runs them on its own cadence. It reports pipeline KPIs upward. It never sleeps.

### Tier 2 — Process (C-Suite Orchestrator)

**Role Analogy:** CEO / VP — the macro coordinator

**Description:**
A Process represents a complete business workflow. It receives target inputs, creates a dynamic dependency graph, schedules child runs, handles parallel branches, and summarizes final business outcomes. Think of it as the project plan that executes itself.

**Example:** "Quarterly Lead Nurture and Activation Campaign" — ingests a CSV of stale leads, fans out qualification calls, routes warm leads to the Deal Closer, generates proposals for ready buyers, and reports conversion metrics.

### Tier 3 — Agent (Manager / Department Head)

**Role Analogy:** Sales Manager / Support Lead — the domain specialist

**Description:**
An Agent manages a specific communication channel or domain. It maintains conversational state, applies domain guidelines, searches the knowledge base, and routes complex requests to specialists. This is where personality lives — tone, empathy, humor, formality.

**Example:** "Sarah — Lead Qualification Phone Rep" — answers inbound calls, qualifies leads against your ICP criteria, books demos on your calendar, and remembers every conversation she's ever had with every prospect.

### Tier 4 — Skill (Specialist / Task Executor)

**Role Analogy:** Contract Specialist / Data Analyst — the focused executor

**Description:**
A Skill is an optimized block of logic focused on a single technical task. It takes raw inputs, runs computations, generates documents, and delivers outputs. No conversation, no personality — just precise, reliable execution.

**Example:** "Contract Generation & E-Signature Routing" — takes customer variables, parses templates, runs ROI calculations, creates a formatted PDF contract, and routes it for signature via DocuSign.

### Tier 5 — Action (Individual Worker)

**Role Analogy:** API Caller / Tool Operator — the atomic executor

**Description:**
An Action is a thin wrapper around a single registered Tool. It represents the interface between the AI Engine and external systems — the smallest unit of work in the platform.

**Example:** "Query Salesforce for Company ID" — calls the CRM API, validates the response format, handles timeouts, and returns the result to the Skill above.

## Section 4 · THE AGENT ANATOMY

**Eyebrow:**
`INSIDE AN AI EMPLOYEE`

**Section Headline:**
Every layer. Configurable. By you or by Pragya.

**Section Subheadline:**
An AI Employee is not a black box. It is eight configurable layers — each visible, tunable, and governed.

### Layer 1 — Identity
Name, title, and role description. The system-prompt charter that defines the employee's boundaries, guidelines, logic gates, and explicit behavior parameters. This is the "job description."

### Layer 2 — Personality Matrix
Precision tuning sliders for six dimensions:
- **Tone** — Professional ↔ Friendly ↔ Empathetic ↔ Assertive
- **Verbosity** — Concise ↔ Moderate ↔ Verbose
- **Empathy** — 0.0 (factual) → 1.0 (deeply empathetic)
- **Humor** — 0.0 (serious) → 1.0 (witty)
- **Formality** — Casual ↔ Formal
- **Custom Rules** — "Never discuss competitor pricing." "Always direct billing disputes to support."

### Layer 3 — Logic Gate
Reasoning mode configuration:
- **ReAct** — Reason-then-Act for linear tasks and database operations
- **Chain-of-Thought** — Step-by-step logic for document drafting and analysis
- **Debate / Multi-Path** — Multiple reasoning paths with critic selection for high-stakes decisions

### Layer 4 — Tool Bindings
Which tools this employee can access — from the 20+ built-in registry. Web Search, Email Suite, PDF Generator, Voice, Sandbox Code Executor, Bank Feed Synchronizer, E-Signature Handler, and dozens more.

### Layer 5 — Knowledge Base
Your company's documents — PDF, DOCX, spreadsheets, and connected sources (SharePoint, Notion, Google Drive, databases). Chunked into 500-character segments, converted to 768-dimension vectors, and searchable by meaning.

### Layer 6 — Memory
The 4-tier memory system that makes your AI Employee smarter over time:
- **Working Memory** — Today's scratchpad
- **Episodic Memory** — Last 10 conversations per contact
- **Semantic Memory** — Vector search over your knowledge base
- **CORTEX Tree Memory** — Deep, hierarchical, compounding cognitive context

### Layer 7 — Governance
Max cost per run. Timeout limits. Human-in-the-Loop checkpoints — pause execution before high-stakes actions (large payments, contract signatures, sensitive communications) and require your approval.

### Layer 8 — I/O Contract
Typed input and output variable schemas. What goes in, what comes out — structured, validated, predictable.

## Section 5 · EXECUTION REASONING MODES

**Eyebrow:**
`HOW THEY THINK`

**Section Headline:**
Three reasoning modes. Each chosen for the work at hand.

### ReAct (Reason-then-Act)
The engine decides which tool to call, runs the tool, observes the results, and loops until complete. Best for linear tasks: database operations, API calls, data retrieval.

**Example:** An Agent receives a support ticket → searches the knowledge base → finds the relevant article → drafts a response → sends it. Four tools, four observations, one resolution.

### Chain-of-Thought
The model writes out its step-by-step logic explicitly before generating final outputs. Best for complex reasoning: document drafting, financial analysis, legal review.

**Example:** A Contract Review Specialist reads a vendor agreement → identifies 14 risk clauses → evaluates each against your legal playbook → generates a redline with annotations → routes for human review. The reasoning trail is visible at every step.

### Debate / Multi-Path
Multiple candidate reasoning paths are generated simultaneously. A critic evaluates, selects, or synthesizes the best answer. Reserved for high-stakes decisions at the Process and Loop tiers.

**Example:** A pricing decision generates three strategies — aggressive discount, value-based premium, and volume tiered. A critic agent evaluates each against your margin targets, competitive positioning, and deal history. The best path wins — and the reasoning is logged.

**Cross-cutting Note (displayed prominently):**
> Whatever the reasoning mode, every step is model-routed. The **Intelligent Router** binds each step to the right brain at runtime — BabyBuddha for most work, a frontier model when the task demands it. You never overpay for intelligence you don't need.
