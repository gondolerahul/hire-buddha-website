## Section 2 · THE FLOW

**Section Headline:**
From signal to assignment in seconds.

**The Orchestrate Flow:**

1. **Signal Intake** — Qualified signals arrive from Perceive (new intelligence, anomalies, alerts) and Engage (deals closed, tickets escalated, candidates shortlisted).

2. **Triage & Classification** — The Comms Triage Agent classifies incoming work by type, urgency, and required capability. Priority is assigned.

3. **Resource Allocation** — The Service Dispatcher identifies the right agent or team for the work. If the capability exists, it's assigned immediately. If it doesn't, the Meta Agent is invoked.

4. **The Meta Agent Builds What's Missing** — When no existing agent, skill, or tool can handle the requirement, the Meta Agent runs its build-loop: understand → structure → assemble → generate → simulate → critique → publish. A new AI Employee appears in the workspace, ready to work.

5. **Execution Tracking** — The Project Orchestrator tracks milestones, SLAs, and dependencies across all dispatched work. Delays are flagged. Blockers are escalated.

6. **Handoff** — Completed work and status updates flow to the Fulfill and Sustain arcs for execution and to the Evolve arc for analysis.

## Section 3 · MEET THE AGENTS

### Service Dispatcher

**Role:** Allocate work and resources across the loop — the routing engine.

**Tools:** Webhooks · Database · REST Connectors

**What it does:** Receives work items and matches them to available agents based on capability, workload, and priority. Handles load balancing across concurrent processes. Triggers parallel execution when multiple agents are needed.

---

### Project Orchestrator

**Role:** Track milestones, SLAs, and dependencies across complex workflows.

**Tools:** Calendar · Task Database · Slack/Teams

**What it does:** Maintains the execution timeline for multi-step processes. Monitors progress against SLAs. Flags delays and bottlenecks. Generates status reports for Pragya and the Evolve arc. The AI equivalent of a project manager who never forgets a deadline.

---

### Scheduling Agent

**Role:** Coordinate calendars across people, agents, and external parties.

**Tools:** Google Calendar · Microsoft Graph (Outlook) · Email

**What it does:** Finds available slots, proposes times, sends invites, handles rescheduling, and manages conflicts. Integrates with the Appointment Concierge in the Engage arc for customer-facing scheduling.

---

### Comms Triage Agent

**Role:** Triage incoming communications — email, Slack, Teams — and route to the right handler.

**Tools:** Email Ingest · Email Classify · Slack/Teams Integration

**What it does:** Monitors your inbox and team channels. Classifies each message by urgency, intent, and topic. Routes to the appropriate agent or escalates to a human. Prevents the "unanswered email" problem and the "wrong person CC'd" problem simultaneously.

---

### Meeting-Notes Agent

**Role:** Transcribe meetings and generate action items.

**Tools:** Voice Transcription · File Writer · Task Database

**What it does:** Records and transcribes meetings. Identifies action items, decisions, and follow-ups. Creates structured notes and distributes them to relevant agents and stakeholders. Tracks whether action items are completed.

## Section 4 · THE META AGENT — THE ORCHESTRATOR'S BUILDER

**Section Headline:**
Any gap in the workforce is filled at runtime.

**Copy:**
The Meta Agent lives in the Orchestrate arc because orchestration is where gaps become visible. When the Service Dispatcher can't find an agent with the right capability, it doesn't file a support ticket — it invokes the Meta Agent.

The Meta Agent:
1. Decomposes the missing capability into required agents, skills, and tools
2. Builds the complete AI Employee — charter, personality, tool bindings, knowledge base
3. Generates any missing tools (self-evolving code)
4. Tests the result against representative inputs
5. Publishes the new employee to the workspace
6. Hands it back to the Service Dispatcher for immediate assignment

**Key Message:**
> Your AI workforce is self-completing. It identifies its own gaps and fills them. The workforce you run tomorrow will have capabilities the one you deployed today doesn't — and no human had to write a spec, hire a developer, or submit a request.

## Section 5 · EXAMPLE SCENARIO

**Section Headline:**
When the loop encounters something new.

**Tuesday, 10:00 AM:**
A client in the logistics industry requests an automated dispatch system for field service crews. No existing agent template covers field-service dispatch.

**Tuesday, 10:02 AM:**
The Comms Triage Agent classifies the request. The Service Dispatcher searches for a matching capability. None found. The Meta Agent is invoked.

**Tuesday, 10:15 AM:**
The Meta Agent has built a "Field Service Dispatcher" agent — with a charter, personality tuned for operational brevity, tool bindings to the Calendar and Webhooks, a new "Route Optimizer" tool (generated code, sandboxed, tested), and a governance profile with HITL gates on crew reassignment.

**Tuesday, 10:20 AM:**
The new agent is published to the workspace. The Project Orchestrator assigns it to the client's process. The Service Dispatcher begins routing field-service requests to it.

**Result:** A capability that didn't exist 20 minutes ago is now live, tested, and working. No development sprint. No hiring cycle. No waiting.
